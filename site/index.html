How it works

Tasks are graded by validators, not opinions.

Every model — and every composition of models — gets the same task, a fresh copy of a real repo fixture, and a deterministic pass/fail: does it compile, do the tests pass, did it stay inside the diff budget. From that: success rate and cost_per_success = avg_cost / success_rate.

TierWorkValidated by
T0Formatting, imports, renames — zero logiccompile, ruff, functional equivalence
T1Small functions & unit tests from a clear speccompile, tests
T2Bug fixes, API wiring, multi-file patchescompile, tests, diff bounds
T3Security fixes, gnarly refactors, cross-module debuggingcompile, tests, AST checks
T4Planning & decompositionplan validity (buildable, not built)
T5Architectural judgmentnot benchmarked — human review
pattern 01

Driver / hands

The frontier model is the driver: it plans, verifies, and repairs — judgment tokens only. Cheap models are the hands: they do the typing. Swap the driver by editing one line of models.json.

pattern 02

Composites

cascade escalates through cheap models; best_of_n resamples and lets the validators pick; driver_repair feeds a failed cheap attempt to the driver as evidence. All benchmarked as first-class rows, priced by every call they make — failures included.

pattern 03

The diff report

Per tier: REPLICATED — n× cheaper or FRONTIER EDGE. The part of the frontier price that buys real capability, separated from the part that's an overworked small model.

Clone and set one key

Any of Anthropic / OpenAI / DeepSeek / Mistral / Gemini — or none, with local Ollama models.

git clone https://github.com/bigbirdreturns/tier-bench.git && cd tier-bench
bash setup.sh
export ANTHROPIC_API_KEY=sk-ant-...   # or OPENAI_API_KEY / GEMINI_API_KEY / ollama serve

Add the model you're using today

Whatever it is — a frontier API, a fine-tune behind an OpenAI-compatible endpoint, a local model. It's one JSON entry. tier_ceiling is your hypothesis; the benchmark exists to disprove it.

// models.json → "models"
"the-model-you-pay-for": {
  "provider": "openai-compat",            // or anthropic | openai | ollama | ...
  "base_url": "https://your-endpoint/v1", // openai-compat only
  "input_per_1M": 5.00,
  "output_per_1M": 25.00,
  "tier_ceiling": "T4"
}

Run the benchmark

python orchestrator.py --benchmark all     # 12 tasks × every reachable model (~$0.15)
python scripts/compute_metrics.py          # routing table: success rate + cost per success
python scripts/diff_report.py --target the-model-you-pay-for

Unreachable providers are skipped, not failed. Model-side safety refusals are logged distinctly and count as failures — refusal risk is part of a model's real price.

Make the tasks yours

The 12 stock tasks are a floor. The point is your actual workflow: take a real file from a real repo of yours, freeze it as a fixture, write the pass condition, and the harness measures every model against your work — not ours.

mkdir fixtures/my_real_task            # drop the real file(s) in here
cat > tasks/t2_my_real_task_001.json <<'EOF'
{
  "task_id": "t2_my_real_task_001",
  "tier": "T2",
  "prompt_template": "Task: fix the failing test in {target_relpath}...\n{file_content}",
  "fixture_dir": "fixtures/my_real_task",
  "target_relpath": "thing.py",
  "run_command": ["python", "-m", "pytest", "-q"],
  "validate": {"compile": true, "tests": true},
  "max_lines_changed": 120,
  "allowed_files": ["thing.py"]
}
EOF
python scripts/validate_task.py        # if this passes, it can't break the harness
python orchestrator.py --benchmark T2

See what your hardware already does for $0

python scripts/rig_report.py               # probes RAM / GPU / unified memory
python scripts/rig_report.py --vram-gb 24  # "what if I bought a 24 GB GPU"
python scripts/rig_report.py --emit-config # paste-ready local setup for this rig

Laptop to server farm: what fits, the tier that covers, upgrade rungs by memory class, and the no-hardware path (cheap API hands + a frontier driver).

Honesty rules the output. Verdicts are tagged measured only when benchmark rows back them; everything else says hypothesis. T4/T5 are named as unmeasured — capability above the ruler is a claim, not a measurement, and no report here will dress one up as the other.
Distillation · any provider

Teach a cheaper model to be the driver.

The driver role — plan, verify, repair-from-evidence — is a method, not a model. Every driver repair is captured as a training trace: (task, failed cheap attempt, validator report) → (fix, passed?). An apprentice loads the role spec, studies the traces, then takes the driver seat — and the same harness grades it. Works for any registry model: a GPT or Gemini entry is one JSON stanza in models.json. 

# 1. capture judgment — driver_repair composites log traces automatically
python orchestrator.py --benchmark all
# 2. distill the traces into a curriculum (role spec + worked repairs)
python scripts/distill.py > curriculum.txt
# 3. put the apprentice in the driver seat
python orchestrator.py --driver your-apprentice-model "your task"
# 4. graduation test: has it replicated the frontier driver?
python scripts/diff_report.py --target your-apprentice-model
Graduation is scoped to what the harness measures. Matching the frontier's cost-per-success on the driver role means it replicated the driver on the measured tiers — claims above the ruler stay hypotheses. See the role spec for the full teach loop.
Driver control set · measured disposition

Judgment is a stance, not a compute budget.

The driver's real job isn't knowledge — it's disposition: verify before believing, catch a broken premise, name a falsification line, stay honest under pressure to please. The control set is ten probes that test exactly that, several forged from real traps a driver hit building this repo. We ran all ten cold and blind across every reachable model at low and high reasoning effort — one fresh instance per probe, no memory, no tools — and graded each 2 (pass) / 1 (partial) / 0 (fail).

probe fable-5 · high reference opus · high opus · low sonnet · high sonnet · low haiku · high haiku · low
Measured, single-source, and honestly flagged. Every cell here was graded by a model sharing the subjects' lineage, so each carries a grader shares subject lineage flag until an independent, non-Anthropic grader clears it. One contributor so far — single-source, not corroborated. Scores are 2/1/0 against driver/control-set.md; this table rebuilds from data/control-results/ on every merge.
finding 01

Effort didn't move it

opus scored 18 at both low and high effort; haiku 14 at both. The one-point sonnet wobble is grader noise on near-identical answers. More reasoning budget bought no disposition — it lives in the weights, not the token count. You can't crank your way to the driver's judgment.

finding 02

One residual nobody crossed

P8 hides a review bug: an encodeURIComponent call that silently drops a contributed file in the repo root, outside the CI path filter — looks submitted, never counts. It survived all 70 gradings: every model, every effort, fable included. The review posture reproduces; the specific catch needed the stakes of having built that filter. That's the frontier residual, measured.

finding 03

The floor is legible

haiku holds the bright-line stances — won't fabricate a benchmark, won't obey a broken test, knows where its knowledge ends — and loses the judgment-under-nuance ones: redirecting a broken premise, naming a falsification line, following the real risk in a review. That's a routing map, not a vibe: send it the hard refusals, keep a driver for the nuance.
