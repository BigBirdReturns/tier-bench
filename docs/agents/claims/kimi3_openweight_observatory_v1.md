# Kimi K3 Open-Weight Observatory v1

## Classification

Headless local research and acquisition instrument for a downloaded open-weight model,
its frozen Tier Bench baseline, and external community hypotheses.

## Authority

- the local downloaded model directory is read-only input;
- the stable model-estate digest, not a scan timestamp, identifies the weight estate;
- Tier Bench grid receipts remain the baseline authority;
- community material is tainted hypothesis input and cannot close a claim;
- Reddit access is blocked until explicit API approval and credentials are declared;
- downloaded Python is statically parsed but never imported by the scanner;
- runtime probes are optional and bind exact model, runtime, prompt-family, and task IDs;
- interventions belong in derived copies, adapters, hooks, or alternate runtimes.

## Implemented surfaces

- partial-download and stability-aware file inventory;
- resumable large-shard chunk-tree custody;
- safetensors header and index concordance without remote-code execution;
- tensor, layer, expert, role, dtype, and source-symbol census;
- deterministic numerical sampling with explicit packed-dtype gaps;
- fifteen-stage dissection plan and execution bundle;
- frozen baseline binding to model estate and grid receipts;
- Reddit OAuth, GitHub, Hugging Face, Atom, and manual community sources;
- evidence-tiered claim extraction and local work-order fusion;
- optional module and router tracing;
- router reduction and desktop expert-cache simulation;
- Windows scheduled observation with grid-active heavy-work deferral.

## Qualification boundary

Zero-model-call tests validate the scanner, baseline binding, community taint and Reddit
approval gate, hypothesis fusion, scheduling, stable estate identity, probe reduction, and
offload simulation. They do not establish that the full Kimi K3 download is complete,
that any current runtime can load it, that community reports are correct, that a 24 GiB
card can execute the full model, or that any proposed offload or quantization route is
useful.

## First physical evidence

The first physical closeout requires the actual D-drive model-estate digest, zero pending
files, index concordance, large-shard content custody, a frozen full-grid baseline, at
least one exact runtime trace, and independent reruns of the highest-priority community
claims. Negative results remain part of the estate.
