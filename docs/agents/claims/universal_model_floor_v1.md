# Universal Model Floor v1

## Classification

Headless model-evaluation control plane. It composes internal Waterline reports, a runtime-attested model registry, external benchmark snapshots, and community claim records into bounded task-family floors.

## Authority

- internal Tier Bench receipts and external acceptance remain authoritative for local routing;
- runtime model identity is required for internal capability observations;
- external benchmark rows remain bounded to their exact comparison cell;
- community records can open or reprioritize experiments but cannot settle a floor;
- social popularity cannot raise evidence tier;
- different benchmark revisions, scaffolds, tools, attempts, context policies, and metrics cannot be averaged;
- Git and the configured local state directory remain the durable record.

## What lands

- full registry conversion from `models.json`;
- alias, surface, runtime, effort, quantization, hardware, and revision identity audits;
- conversion of pairwise Waterline reports into common observations;
- one internal floor and Pareto frontier per task family;
- a complete adequate, wall, collecting, or unmeasured matrix across every registered model;
- focused Opus 5 versus Fable 5 delta reports;
- Hugging Face official benchmark discovery and leaderboard ingestion;
- Hugging Face model-centric eval ingestion;
- GitHub, Reddit OAuth, Atom, JSON, CSV, and JSONL source adapters;
- immutable raw source snapshots and sync receipts;
- external comparison distributions;
- Windows scheduled sync and recomputation;
- zero-model-call tests and permanent CI.

## Qualification boundary

The implementation is qualified by deterministic unit tests and fixture ingestion. It does not establish a real Opus/Fable waterline, a real full-model floor, or agreement with any external benchmark until actual runtime-attested Tier Bench receipts and source snapshots are supplied.

## Failure default

Unknown aliases, missing runtime IDs, runtime mismatches, source conflicts, malformed observations, incompatible benchmark cells, missing costs, insufficient distinct tasks, and missing attention or defect audits remain visible and fail closed under the configured rule.

## First physical pass

Ingest the active Opus/Fable grid, generate the full registry from `models.json`, synchronize official benchmark sources, compute the initial floor, and review every identity conflict and external discrepancy before changing production routing.
