# CART0 repository-context net-effect pilot 0

Date: 2026-07-16/17

Disposition before dispatch: **EXPLORATORY SYNTHETIC MECHANISM PILOT**

## Question

With planner model and effort held constant, does a repository-addressed
planner-to-Spark workflow complete the same synthetic repository task as often
as the planner acting alone, while producing durable decimal-addressed context
that a fresh bounded hand can navigate?

This is the missing provider/model-quality rung after the deterministic CART0
Select/Compose bridge. It is not the CART0 anchor benchmark and cannot mint a
capability, context-window, model-ranking, or causal verdict.

## Established principles reused

- `data/continuity/CART0_CONTRACT.md`: actor-relative position, freshness,
  retrieval pointers, and decision-boundary resurfacing.
- `docs/cart0-anchor-prototype.md`: stable Dewey-style IDs, hard context
  budgets, pointer rehydration, and external authority.
- `docs/THE-RECURRING-DEFECT.md`: stable knowledge leaves fallible attention

## Frozen arms

Two matched replicates use byte-identical initial repositories.

- `PLANNER_ALONE`: `gpt-5.6-luna@high` must plan, implement, and validate in
  one call. It may update CART0 state but may not create child calls.
- `PLANNER_TO_SPARK`: one `gpt-5.6-luna@high` call may update CART0 planning
  cards only. One fresh `gpt-5.3-codex-spark@low` call then receives only a
  short role instruction pointing it to `000.000.INDEX` and the authorized
  crate. Spark must retrieve task terrain from the repository, implement, and
  run the exact validator.

Call order alternates by replicate. Maximum provider calls: six. No retries.

## Context bound

The complete non-Git subject repository must remain at or below 32,768 UTF-8
bytes before hand dispatch. This deliberately leaves orders of magnitude of
headroom below Spark's model context. Exceeding the bound is a typed planning
failure and prevents the hand call.

## Admission and outcomes

The controller, not model prose:

1. computes changed paths;
2. rejects task, validator, documentation, authority, or out-of-scope edits;
3. reruns the exact visible validator with the pinned controller interpreter;
4. preserves the actual binary Git patch and its SHA-256;
5. records CLI identity, prompt, events, usage, parent/final state, and call
   order.

A valid arm execution that fails its validator is a system failure and remains
part of the exploratory result. Transport, CLI identity, baseline mismatch, or
controller failure is administrative and suppresses paired interpretation.

## Frozen interpretation

Report only observed completion, repository/context bytes, calls, tokens,
duration, changed paths, and refusal classes. Two replicates are mechanism
debugging, not statistical evidence. Terra/Luna hands, recursive planners,
hidden grading, real projects, and the CART0 benchmark require separate rows.
