# 010.100 Task — crossover_v1 (CRATE-CROSSOVER-1)

**Question:** the honest doctrine test. Amortization_v1 measured fable-vs-fable
and left the real comparison open: does a fable DESK dispatching haiku HANDS
beat plain haiku TENANTS working payload-inline? Same three-tiny-task shape;
this time D is genuinely cheap.

## The three tasks (identical text for both arms)

- **X1** — `scripts/burn_report.py`: add `--vendor {anthropic,openai}` filter.
  With `--json`, the `vendors` object contains ONLY the selected vendor and the
  session rows are filtered to it. Without `--vendor`, behavior unchanged.
- **X2** — `scripts/crate_new.py`: add `--list` flag: with `--dir D`, print one
  existing crate directory name per line and exit 0 WITHOUT creating anything.
  `--name` not required when `--list` given.
- **X3** — `scripts/dispatch.py`: add `--dry-run` flag: print the resolved hand
  command and referee command, then exit 0 WITHOUT running either and WITHOUT
  writing a receipt.

Each task: modify only its named script; keep all existing flags working.

## Arms (one attempt each; failures are data)

- **Arm D (tenant, runs FIRST on the clean baseline):** three separate
  `claude -p --model haiku` sessions, one per task, task text inline, tools
  Read/Edit/Bash(+PowerShell). No crates, no pointers.
- **Arm C (desk):** one `claude -p --model fable` driver session told to
  operate per docs/CRATE_OPS.md: author three mini-crates (card + frozen
  referee each) under this crate's `arm_c/` dir, dispatch three haiku hands
  via `scripts/dispatch.py` (FOREGROUND — background hands die in -p mode,
  measured in amortization_v1), adjudicate, report. Hands' allowedTools
  include PowerShell (Windows harness pushes it — same receipt).

## Protocol invariants

1. Baseline = the freeze commit of this crate. `git checkout -- scripts/`
   between arms; each arm's diff saved as `arm_{d,c}.patch` in this crate
   BEFORE reset. No cross-arm tree contamination (amortization defect D2/D3).
2. The frozen desk referee (`referee.py`, this dir) is the ONLY pass
   criterion, run at the desk after each arm. Arm C's self-authored referees
   are its own ceremony, not the judgment.
3. Metering: per-session `total_cost_usd` + final context tokens from output
   JSON / sidecars; both arms land on the two-vendor ledger.
4. One attempt per arm. No retries; a failed arm is recorded as failed.

## Measured axes

Dollars per arm (all-in, driver + hands), summed final context tokens per arm,
tasks passed per arm (0-3 each, desk referee).
