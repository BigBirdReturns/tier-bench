# 010.100 Task — referee_kernel_contract_v1

**Status: CONTRACT FROZEN — implementation card NOT authorized.**
This card publishes the referee semantics that `tier run` already implements
(`docs/tier-runner.md`, `tier_runner/core.py`,
`schemas/tier_run_receipt.schema.json`) as a stable contract any host can
call. It formalizes existing behavior; it does NOT create a second execution
system and does NOT broaden `tier run` into an orchestrator.

## The referee function

Operator freezes, before dispatch: base commit, allowed scope, task bytes,
immutable acceptance command. Host invokes a cartridge and returns a
candidate. The referee evaluates the candidate outside the authoring model
and emits exactly one terminal class: `ACCEPTED` | `REJECTED` | `ERROR`.

## Guarantees retained from current `tier run` (now contractual)

- The operator checkout remains untouched.
- The candidate sees a restricted, Git-free packet (declared `--files` scope
  only).
- The acceptance command cannot silently author the result.
- The emitted patch represents the exact candidate tree tested.
- None of the following can produce `ACCEPTED`: missing telemetry,
  out-of-scope writes, manifest drift, mutable acceptance command, failed
  cleanup, reused session.

## Failure reason codes (closed enum — a guarantee only if the vocabulary is closed)

`ACCEPTANCE_MUTATED` | `SCOPE_ESCAPE` | `BASE_DRIFT` | `EMPTY_PATCH` |
`ACCEPTANCE_FAILED` | `CANDIDATE_TAMPERED` | `RECEIPT_CORRUPT` |
`TELEMETRY_MISSING` | `CLEANUP_FAILED` | `SESSION_REUSED`

Every non-`ACCEPTED` termination carries exactly one code. An
undifferentiated nonzero exit is a contract violation.

## Negative witnesses (the new work; frozen as required fixtures)

Seven adversarial fixtures, each a tiny repo + a tampering step + the exact
expected reason code:

1. acceptance-command mutation → `ACCEPTANCE_MUTATED`
2. write outside declared scope → `SCOPE_ESCAPE`
3. changed base bytes between freeze and evaluation → `BASE_DRIFT`
4. empty candidate patch → `EMPTY_PATCH`
5. acceptance command fails honestly → `ACCEPTANCE_FAILED` (`REJECTED`)
6. verifier-side modification of the candidate → `CANDIDATE_TAMPERED`
7. deliberately corrupted receipt → `RECEIPT_CORRUPT`

## Boundary

Hosts own sessions, credentials, worker lifecycle. The referee owns the
verdict. No host, scheduler, or model narration may override or re-classify a
terminal class after emission.
