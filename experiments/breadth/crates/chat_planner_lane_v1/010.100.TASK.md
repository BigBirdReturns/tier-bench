# 010.100 Task — chat_planner_lane_v1

**Status: CONTRACT FROZEN.** This card defines the chat-surface planner lane:
using a subscription chat product (ChatGPT Pro high-effort today; any
equivalent surface tomorrow) as a T4/T5 planning cartridge. No implementation
is required to use this lane — it is a protocol for the operator and driver,
usable immediately by hand. Desk integration (an AWAITING_PLANNER hold state
in Monster Wrangler) is a post-smoke implementation card.

## Why this lane exists

The planning tier (T4/T5: decompose, architecture tradeoffs, adversarial
review of decisions) is the most expensive tier per token and the least
deterministic. The Pro chat surface is fully subsidized, does not draw on the
Codex or Claude metered quotas, can browse the public cloud repo itself, and
runs high effort. Latency (minutes to an hour) is acceptable because the
queue holds; planning is never on the critical path of a running hand.

## The cartridge definition

- **Role:** planner / adviser / adversarial reviewer. NEVER solver of graded
  tasks (that contaminates the benchmark), NEVER grader, NEVER closure
  authority.
- **Cost basis:** `subscription-subsidized` — recorded as $0 marginal in the
  ledger, with the surface + effort named, so replication claims never hide
  a subsidy.
- **Transport:** human paste, both directions. Packet out: a self-contained
  prompt containing the question, the decision constraints, and repo
  pointers (the surface may browse the public repo; the packet still quotes
  any load-bearing bytes so the answer binds to exact content, not to
  whatever the repo says when it looks). Response in: pasted verbatim into
  the driver session or committed as a file.
- **Evidence class:** every output is `single-source` and
  `capability_basis: hypothesis`. A chat plan becomes actionable the same
  way any hypothesis does — a driver adjudicates it, a deterministic
  referee or measured run confirms it. Chat narration never outranks the
  harness (constitution §1).

## Receipt discipline (what makes a paste evidence instead of vibes)

A planner exchange worth keeping is committed as a receipt file containing:

```text
schema            "tier-bench/chat-planner-exchange@1"
surface           e.g. chatgpt-pro
effort            e.g. pro/high
packet_sha256     hash of the exact prompt bytes sent
response_sha256   hash of the exact response bytes received
repo_ref          commit the packet's quoted bytes came from
disposition       adopted | adopted-with-corrections | rejected | informational
adjudicated_by    the driver session/commit that ruled on it
```

Precedent: tonight's kernel-contract decision was exactly this lane run by
hand — a chat-surface decision packet, driver-adjudicated (corrections
applied), then frozen into cards. That exchange is the lane's first
informal receipt; this card makes the next one formal.

## Boundaries (frozen)

1. Planner output may propose graders, pass criteria, or ledger changes;
   it may never BE the commit that changes them (those stay GATED).
2. No solver packets for hidden-graded tasks go to this lane.
3. The subsidy is named in every ledger row; "free" never becomes "costless"
   in a replication claim.
4. If the surface starts executing code or fetching private state, it has
   left this contract; stop and re-adjudicate the lane.
