# 010.100 Task — monday_board_v1

Projection-only; explicitly NOT Agent Deck.**

## What it is

A read-only board the operator opens on Monday morning (phone or desktop) and
knows, without asking: what ran, what it cost, what's in flight, what's blocked
on them, and how the week's quota is tracking. "The LLM navigates, the shards
prove" in dashboard form: every number on the board must trace to a committed
byte (queue row, receipt, burn log, git log). No number may be invented,
estimated, or smoothed by a model.

## Hard boundary (frozen)

- READ-ONLY projection. The board holds nothing, closes nothing, dispatches
  nothing, and writes nothing into evidence. Rebuildable from repo bytes at any
  time; deleting it loses nothing.
- NOT Agent Deck: no buttons that spawn work, no chat, no closure controls.
  Interactive client work stays behind the contracts-first gate.
- Renders as a self-contained page (Artifact or single HTML file). v0 is a
  desk-generated snapshot; a scheduled re-render is allowed but the generator
  must remain a pure function of repo state.

## Sections (v0)

1. **Decisions waiting on operator** — queue rows with `operator` owner or
   gated states, each linking its evidence path.
2. **Queue state** — active rows: id, owner, state, one-line note.
3. **Receipts landed** (last 7 days) — from git log + crate receipts: what,
   who (hand/tank), cost where receipted.
4. **Tanks & spend** — per-tank spend actually receipted (Anthropic hands $,
   GPT dispatches count; subscription quota gauges only where a real meter
   exists — no fabricated percentages).
5. **In flight** — dispatched-but-unadjudicated hands, if any.

## Acceptance (v0)

Board renders from committed bytes only; every figure has a source path; a
reader can click from any number to the file that proves it (or see the exact
path named). Desk verifies by spot-tracing 3 numbers before publish.
