# Mobile-Game Interaction Doctrine — Program of Record (Legacy + Rebuild)

## 1. THE GAME

**Legacy build** (`Program of Record — Current Build/`): a Monopoly-genre satire strategy board game. Players race pieces (tank/jet/ship/helo/satellite, drawn as flat 2D canvas billboards — `build/por-pieces.js`) around an 11×11 grid of 40 spaces (`build/por2-game.jsx:213-220`, `build/por2-data.jsx:80-130`). Core turn is a fixed 5-beat spine (file header comment, `por2-game.jsx:1-7`):
**MOVE → resolve SPACE → one PROGRAM ACTION → REACTION window → optional push-your-luck MILESTONE.** Every beat is a single discrete choice (roll, buy, pick one of nine program actions, react-or-pass, risk-a-milestone), never a spatial manipulation.

**Rebuild** (`rebuild/`): the board is gone entirely. Per `rebuild/docs/SUPERSESSION_LEDGER.md` (row SUP-009), the 40-space track/roll-and-move geometry was deliberately retired, replaced by "explicit fiscal clock, exposure, and consequence events." A "negotiation scene" is now a short, scripted sequence of discrete commands over one procurement negotiation — `inspect_evidence, make_offer, counter_offer, accept_offer, refuse_offer, advance_consequence, sponsor_repair, defer_repair, publish_record` (`rebuild/packages/kernel/src/types.ts:170-179`) — following a mandatory five-beat arc: attractive benefit offered → delayed burden returns → an excluded payer is identified → a costly shared repair can be sponsored/refused → the official closeout can diverge from the sealed ledger (`rebuild/docs/PRODUCT_HYPOTHESIS.md:9-18`). The live thin shell for this is `rebuild/apps/hook/`; `rebuild/probes/` (which the mission pointed at by name) is an **archived**, disposable genre bake-off, not the live UI (`rebuild/probes/ARCHIVED.md:1-7`).

## 2. TOUCH DOCTRINE

**Decision input vs. navigation input, cleanly separated (legacy).** Every rule-affecting choice — roll, buy, bid, pick a program action, react, risk a milestone — is a plain `<button onClick>`; a full-codebase grep found **zero** `onDragStart`/`onDrop`. This is deliberate: `por2-game.jsx:2956` — *"Do not add a React onClick: the runtime's pointer-up selector would then toggle twice."* The board itself (a non-decision layer) uses raw **Pointer Events** (one listener set for mouse+touch+pen) to drive three gestures simultaneously (`index.html:1701-1743`):
- 1-pointer drag → pan camera (6px commit threshold before it "moves")
- 2-pointer pinch (tracked in a `Map`) → zoom, clamped 0.4–2.3×
- tap (pointerdown→pointerup, no movement) → select/deselect a tile — comment cites "precedent: Arknights placement tap" (`index.html:1736`)
- mouse wheel → zoom (separate path)

**Codified touch-target contract (legacy).** `docs/POR_PRESENTATION_QOL_STANDARD.md` §3: 48×48 CSS px minimum, 52×52 under `@media(pointer:coarse)`, 8px gutters between adjacent primary targets — explicitly benchmarked as *more conservative* than Apple HIG/Material. Board sprites get **invisible tap proxies larger than the visible sprite** rather than inflating the art (`docs/POR_BOARD_PRECEDENTS.md`). Other concrete accommodations: `touch-action:none` on the board canvas so gestures aren't hijacked by the browser (`index.html:1125`); `viewport-fit=cover` + `env(safe-area-inset-bottom)` for notched phones (`index.html:5, 472, 610`); `user-select:none`/`-webkit-touch-callout:none` globally to kill iOS long-press callouts (`index.html:1121`); breakpoints from 360×640 phone to 3840×2160 4K/table display; Electron's `BrowserWindow` still enforces `minWidth:320, minHeight:568` (`desktop/main.cjs:91`) — the "desktop" app was built resizable down to phone dimensions.

**Zones/state legibility (legacy).** A `TileStateHooks` component renders selection/reach/threat as three independent, **shape-coded** markers — bracket, chevron, hazard-stripe — never color alone (`por2-game.jsx:2970-2976`; contract: `POR_PRESENTATION_QOL_STANDARD.md` §3, "color never carries the rule alone"). Whose turn it is flows through one function, `porDecisionOwner()` (`por2-game.jsx:277-286`); when it isn't the local player's turn, the whole decision surface is `inert`-locked and desaturated (`porSetFocusLock`, `por2-game.jsx:71-86`; CSS `index.html:86`). A pass-and-play "HandoffCard" fully occludes the screen between turns, backstopped independently in both JS (`inert=true`) and CSS in case the JS layer fails (`index.html:27, 598-602`).

**Illegal-move / error handling (legacy).** Nothing is "attempted then refused" — illegal actions are simply not rendered as clickable, and **every disabled control states its unmet condition inline** (`CAN'T AFFORD`, `DEBT CAP`, etc. — `por2-game.jsx:152-155, 3537, 3616, 3670`), codified as a hard requirement in `docs/POR_1AM_STRANGER_STANDARD.md` §6 ("Disabled control without reason → 'the game is broken'").

**Feedback on action (legacy).** A single gateway `window.POR_FX.event(kind, detail)` drives short, speed-scalable 5-beat animations (Anticipate→Commit→Impact→Consequence→Aftermath, `docs/POR_SIGNATURE_SPECTACLE_CONTRACT.md` §2) that always resolve to a **static causal-receipt sentence** legible with motion/sound off. Sound (`build/por-sfx.js`) and haptics (`navigator.vibrate`, distinct patterns per event type, gated on prior user gesture — `index.html:1749-1760`) are explicitly declared *redundant* channels, never sole information carriers. Screen-shake was tried and explicitly removed: `index.html:1598` — *"(screen-shake removed — replaced by haptics + sound)."*

**Rebuild's touch doctrine is much thinner** — it's a button-only UI with no drag/gesture/native-touch code anywhere. What it does carry forward: 44px minimum touch targets in CSS (`apps/hook/styles.css:187-188`), a `<meta viewport>` tag, `overflow-x:hidden; min-width:320px` phone guard, and one sharp new idiom — an `event.detail > 1` guard on every button so a double-tap landing on a re-rendered DOM element after state change can't fire the action twice (`apps/hook/src/app.ts:64-78`). This whole matrix is verified by an automated Playwright pass at phone (375×812, `hasTouch:true`), laptop (1366px), and 4K (3840px) widths, checking no-horizontal-overflow, 44px targets, reduced-motion-safe static text, and grayscale legibility (`rebuild/scripts/hook-foreground-review.mjs`; `rebuild/evidence/foreground/REVIEW_RECEIPT.json`) — but the project's own docs repeatedly disclaim this as engineering hygiene, *not* literal human/mobile usability evidence (`STATUS.md:154-155, 224-227`).

## 3. WHAT A GAME KNOWS THAT DASHBOARDS DON'T

1. **Separate "what am I deciding" input from "how am I navigating" input, and unify the latter under Pointer Events.** The legacy board runs pan/zoom/select on one listener set that treats mouse, touch, and pen identically (`index.html:1701-1743`), while every consequential decision stays a plain button. A receipts board doing the same — one gesture layer for browsing/inspecting a data surface, one dumb-button layer for committing an action — gets touch-parity for free instead of maintaining parallel mouse/touch code paths.

2. **State never rides on color alone — pair it with shape.** `TileStateHooks`' bracket/chevron/hazard-stripe grammar (`por2-game.jsx:2970-2976`) and the rebuild's own grayscale-verified legibility pass (`REVIEW_RECEIPT.json:87-90`) both encode the same rule. A receipts board flagging "disputed / pending / cleared" should do the same — icon or pattern, not just a red/yellow/green chip.

3. **A disabled control must say why, inline, every time.** `docs/POR_1AM_STRANGER_STANDARD.md` §6 treats a silently grayed-out button as a defect ("the game is broken"). An operator client's "can't approve this receipt" button should carry its blocking reason the same way `por2-game.jsx` does with `data-por-disabled-reason`.

4. **Ownership of the current decision must resolve through one function, everywhere.** `porDecisionOwner()` (`por2-game.jsx:277-286`) is the single source of truth every panel reads to decide who acts next and to lock/dim the UI otherwise. Trillian, juggling multiple actors/queues, wants exactly this: one authoritative "whose turn/task is this" resolver instead of ad hoc per-panel checks.

5. **Feedback should be redundant across channels but never depend on any one of them.** Sound and haptics are explicitly "acknowledgement," never information (`por-sfx.js` header comment); the ground truth is always a static causal-receipt sentence. A dashboard notification (toast + badge + sound) should follow the same rule: strip any one channel and the state is still fully legible from what's left — directly useful given the operator may be glancing at a phone with sound off.

6. **Show two accounts side-by-side and prove they agree (or don't) with a visible digest, instead of quietly merging them.** The rebuild's "official narrative vs. authoritative ledger" split, with a rendered SHA-256 proving the sealed ledger is unchanged regardless of narrative (`apps/hook/src/app.ts:413-440`), is precisely the receipts-board problem: a human-editable story layer must never silently redefine the machine-verified truth layer. Render both, prove agreement.

7. **Gate raw data behind one deliberate tap ("inference before explanation") rather than dumping it on load.** The rebuild's accounting breakdown only appears after the player taps "Reveal the accounting" (`apps/hook/src/app.ts:464-484`, tested as `"the accounting waits for the player"` in `REVIEW_RECEIPT.json:44-48`). A receipts board's raw ledger/audit trail should sit one tap away under a summary, not be force-fed above the fold.

8. **Bound and enforce attention budgets as defects, not aspirations, and give re-orientation a deterministic short recap.** `docs/POR_1AM_STRANGER_STANDARD.md` §2 sets hard numbers (CPU wait <3s, turn 30–75s, handoff readable in one glance) and `por-story.js` caps its "what happened" recap at 5 prioritized lines. An operator dashboard resurfacing after interruption should have the same: a capped, priority-ordered "what changed since you looked away" line, not a raw event dump.

## 4. REBUILD DELTA

Per `SUPERSESSION_LEDGER.md` and `STATUS.md`, the rebuild made a hard, explicit trade: it deleted the entire visual/spatial game-board metaphor (SUP-009, board/track/roll-and-move — "verified" retired) and the presentation-coupled rules code (inline `render()`/SFX/`porFx` calls inside rule bodies, SUP-011) in favor of a pure, headless, deterministic kernel that emits typed events into a hash-chained journal, with any UI treated as a separate, optional, "presentation only" shell reading kernel-projected state (`apps/hook/src/app.ts:14-18`). The stated reason isn't aesthetic — it's evidentiary: Electron + global mutable channels (`window.__POR_*`) and `Math.random`/`Date.now`-driven scheduling couldn't be verified byte-for-bit reproducible or replayed as evidence (SUP-001–SUP-008, SUP-010). "Winning" as the organizing frame was also dropped (SUP-016) in favor of "consequence comprehension, agency, and record-versus-ledger truth."

The cost of that trade, stated candidly by the project itself: presentation/mobile/touch work is never authorized as a first-class deliverable at any milestone (`PRODUCT_HYPOTHESIS.md:86`, `R6_MILESTONE_CHECKPOINT.md:16-18`) — it happens opportunistically on top of the kernel, and every touch/foreground check that does exist is repeatedly disclaimed as *not* proving real human or mobile usability (`STATUS.md:154-155, 224-227`). Where the legacy build had a deep, load-bearing touch doctrine (Pointer Events camera, shape-coded state, haptics, spectacle contract), the rebuild has almost none of that surface area left — what survives is narrower but sharper: 44px targets, no-horizontal-overflow at phone/laptop/4K, reduced-motion-safe static text, grayscale-safe meaning, and the new double-tap idempotency guard. The rebuild's real innovation isn't touch interaction at all — it's the narrative-vs-ledger legibility pattern (§3.6 above), which is a data-trust doctrine, not a gesture doctrine.
