# 020.100 Acceptance — frozen predicates binding the future implementation card

Driver-authored, frozen. If it seems wrong, it is not: match
[010.100](010.100.TASK.md) exactly.

The implementation card, when authorized (post-smoke only), passes only when a
deterministic referee proves ALL of:

1. **Determinism:** two runs on identical fixture inputs produce byte-identical
   decisions after removing `observed_at`.
2. **Fail closed:** each of {missing envelope, truncated manifest, malformed
   snapshot, unresolvable evidence index} yields `NO_DECISION` with the
   matching enum reason; exit code alone is never the signal.
3. **No hypothesis-as-measurement:** a fixture whose only capability source is
   a models.json `tier_ceiling` cannot emit `capability_basis: measured`; the
   schema validator must reject a doctored decision that tries.
4. **Staleness:** a snapshot fixture older than `snapshot_max_age` yields
   either `NO_DECISION(SNAPSHOT_TOO_STALE)` or a decision whose `quota_basis`
   is `derived`/`unknown` with staleness named in `route_reason`.
5. **No credentials:** serialized output of every fixture run matches none of
   the referee's credential patterns (authorization headers, provider key
   prefixes, token-shaped strings).
6. **No execution:** kernel invocation under the referee's subprocess/network
   tripwire records zero spawned processes and zero opened sockets.

The referee is a committed script, frozen before the implementation hand is
dispatched; the hand may run it, never edit it.
