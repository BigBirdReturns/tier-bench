# 010.100 Task — desk_guard_v1

Extend `experiments/breadth/hooks/session_sentinel.py` with a DESK GUARD:
meter tool-result BULK entering the chat context and inject warnings on
PostToolUse. Keep ALL existing behavior (cost tiers, dedup, hard cap,
fail-open) exactly as is — the referee re-runs the whole existing sentinel
suite. Read the file's docstring first; match its style and fail-open rules.

## Counting (inside `scan_new`, for every parsed transcript row)

For every row whose `message.content` is a list, examine each element that is
a dict with `"type" == "tool_result"`. Its text length in characters is:

- `content` is a str → `len(content)`;
- `content` is a list → sum of `len(item["text"])` over items that are dicts
  with `item.get("type") == "text"` and a str `"text"` value;
- anything else (missing, int, None, weird nesting) → 0. NEVER raise.

Proxy tokens for one tool_result block = `chars // 4`. Rows are counted
whether or not they carry usage; message-id dedup does NOT apply here (each
row is scanned once because the byte offset advances).

## Sidecar state (new keys, same state file)

- `bulk_tokens`: cumulative proxy tokens, all tool_result blocks ever scanned.
- `bulk_biggest_single`: max proxy tokens of any single tool_result block.
- `bulk_pending_single`: max single block seen since the last PostToolUse
  evaluation — `scan_new` sets it to `max(previous value, this scan's max)`
  so a PreToolUse or UserPromptSubmit scan can never swallow a pending
  warning; ONLY the PostToolUse handler resets it to 0 (after reading it,
  every PostToolUse, warn or not).
- `bulk_warned_mult`: int, last cumulative multiple warned about (default 0).

## Thresholds (env-overridable ints, fail-open to defaults on bad values)

- `TIER_SENTINEL_BULK_SINGLE` — default 2000 proxy tokens.
- `TIER_SENTINEL_BULK_TOTAL` — default 20000 proxy tokens.

## Injection (PostToolUse ONLY)

After the existing cost logic, evaluate:

(a) `pending = bulk_pending_single` (then reset it to 0). If
    `pending > TIER_SENTINEL_BULK_SINGLE`, add:
    `[desk-guard] a single tool result of ~{pending} proxy tokens just landed
    in this chat context (limit {single}). Bulk belongs in a hand — delegate
    per docs/CRATE_OPS.md; every future turn re-pays rent on every token of
    it.`

(b) If `bulk_tokens // TIER_SENTINEL_BULK_TOTAL > bulk_warned_mult`, set
    `bulk_warned_mult = bulk_tokens // TIER_SENTINEL_BULK_TOTAL` and add:
    `[desk-guard] cumulative tool-result bulk in this chat ≈ {bulk_tokens}
    proxy tokens (crossed {mult} x {total}). Bulk belongs in a hand —
    delegate per docs/CRATE_OPS.md; every future turn re-pays rent on every
    token of it.`

Numbers are plain integers (no thousands separators). PostToolUse must emit
AT MOST ONE JSON object on stdout: if a cost-sentinel warning and desk-guard
message(s) are both due, join them with `"\n"` into a single
`additionalContext` (cost message first; keep the existing `systemMessage`
rule for cost-tier crossings unchanged). If only desk-guard messages are due,
emit them alone in `additionalContext` with the same hookSpecificOutput
shape. Always `_save` the state afterwards.

Everything fails OPEN like the rest of the file: bad rows count 0, bad env
falls back to defaults, exceptions are already swallowed by `main()`.
