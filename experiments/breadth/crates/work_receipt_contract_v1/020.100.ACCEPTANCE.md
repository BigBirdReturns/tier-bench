# 020.100 Acceptance — frozen predicates binding the future implementation card

Driver-authored, frozen. If it seems wrong, it is not: match
[010.100](010.100.TASK.md) exactly.

The implementation card, when authorized (post-smoke only), passes only when a
deterministic referee proves ALL of:

1. A valid fixture receipt chain (decision → attempt → terminal) validates
   end to end by hash linkage alone, offline, with no store beyond the named
   files.
2. Each rejection class in 010.100 has a fixture that fails with exactly that
   machine-readable class: orphaned decision, missing content binding,
   contradictory terminal states, duplicate terminal for one attempt,
   nonexistent predecessor, malformed `unlocks`/`blocks`, and an
   `external_refs` entry attempting to override the referee verdict.
3. A receipt naming an unreachable predecessor validates as
   `UNVERIFIED_PREDECESSOR` (labeled), not as pass and not as hard error.
4. Every fixture receipt also passes `schemas/tier_run_receipt.schema.json`
   where its fields overlap — the extension is additive, proven by running
   both validators on the same bytes.
5. The validator never mutates any input file (byte-compare before/after).

The referee is a committed script, frozen before the implementation hand is
dispatched; the hand may run it, never edit it.
