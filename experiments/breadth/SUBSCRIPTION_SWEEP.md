# Subscription-surface breadth sweep

This lane measures models available through the user's ChatGPT/Codex subscription surface. It is intentionally separate from the API-backed cross-provider runner.

The subscription surface is a quota and UI/tooling surface, not an API-billed telemetry surface. A pass/fail result is valid only when a real candidate was generated by a selected subscription model, saved outside the model context, and then graded locally with the hidden grader. Token counts, cache counts, and dollar costs remain unavailable unless the subscription surface exposes exact usage for that model call.

## What this records

Each subscription-surface run records:

- the exact UI/Codex model label selected by the user
- the task, phase, and trial
- whether the model was available, quota-blocked, or produced a candidate
- the local hidden-grader result after candidate generation
- a candidate hash for grade rows
- subscription-surface telemetry labels in `extra`

It does not record API cost, API billing reconciliation, or exact token counts unless the surface exposes them.

## Ledger extension

`experiments/breadth/subscription_run.py` uses `experiments.breadth.ledger.log_call` without changing the ledger schema. Subscription-specific fields are stored in `extra`:

- `surface="chatgpt_codex_subscription"`
- `selected_model_label`
- `telemetry_class="subscription_surface"`
- `token_accounting`: `available`, `unavailable`, or `estimated`
- `cost_accounting`: `api_billed`, `subscription_quota`, or `unavailable`
- `quota_status`, when visible
- `parent_attempt_id`
- `candidate_sha256`, when a candidate is graded

Rows emitted by this lane use zero token/cache counts and zero cost unless exact telemetry is exposed. That is not a claim of free execution. It is a claim that subscription usage is not API-billed telemetry in this measurement lane.

## Manual sweep loop

1. Edit `experiments/breadth/subscription_models.example.json` into a run inventory using the exact model labels visible in the user's ChatGPT/Codex UI.
2. Emit public-only prompts:

   ```bash
   python experiments/breadth/subscription_run.py \
     --selected-model-label "<exact UI label>" \
     --task-id all \
     --phase solo \
     --trial 1 \
     --prompt-dir /tmp/subscription-prompts
   ```

3. Select the matching model in ChatGPT/Codex.
4. Paste the emitted prompt for one task.
5. Save the model's candidate output to a file.
6. Grade the saved candidate locally:

   ```bash
   python experiments/breadth/subscription_run.py \
     --selected-model-label "<exact UI label>" \
     --task-id task01_parse_duration \
     --phase solo \
     --trial 1 \
     --candidate-file /tmp/candidate.py
   ```

7. Repeat for K trials, all valid breadth tasks, and any harness phase being measured.
8. If the model is visible but unavailable or quota-blocked, record a blocked row:

   ```bash
   python experiments/breadth/subscription_run.py \
     --selected-model-label "<exact UI label>" \
     --task-id task01_parse_duration \
     --phase solo \
     --trial 1 \
     --blocked \
     --quota-status "quota exhausted"
   ```

## Harness phase

Harness-phase subscription runs are valid only when the lens workflow itself is public. Do not paste hidden grader contents, hidden answer keys, or hidden validator logic into the selected model. The hidden grader remains local and runs only after a saved candidate exists.

## Non-claims

This lane must not claim:

- that every OpenAI model exists for every user or plan
- that subscription use has API-equivalent cost accounting
- that token counts are known when the UI does not expose exact usage
- that a model passed or failed without a saved candidate and local hidden-grade row
- that a quota-blocked or unavailable model produced a capability result

The purpose is to map what the user's subscription can actually reach without converting subscription access into fabricated API telemetry.
