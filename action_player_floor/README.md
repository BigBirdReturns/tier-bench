# AXM Action Player Floor v1

The Action Player Floor is the consolidated contract that keeps an authored action
game attractive, responsive, replayable, replaceable, and honest.

It exists because AXM produced two incomplete halves:

```text
exact Arc and World authority with weak player representation
+
credible player representation with a separate invented gameplay runtime
```

Neither half is an acceptable product. The floor requires one chain in which the
version that looks and feels like the game is also the version whose exact trace Arc
replays and accepts.

## Constitutional chain

```text
real Arc challenge
→ exact action specification
→ World input ingress
→ bounded input frames
→ Arc deterministic state and semantic cues
→ exactly one World presentation adapter
→ provisional World candidate
→ exact Arc replay
→ accepted Arc receipt
→ Arc-authored consequence
→ next playable experience
```

No browser, Unity, Windows, Quest, fallback, or promotional build may implement a
second damage, parry, dodge, enemy, mechanism, objective, route-benefit, checkpoint,
or outcome law.

## Governing separations

```text
Arc law                  != World presentation
semantic cue             != cosmetic mapping
input ingress            != action timing
conformance fixture      != player product
engine qualification     != human comprehension
provider recommendation  != product authority
candidate                != accepted product
evidence                 != mandate
```

There is no aggregate readiness percentage. A missing Arc replay, primitive player
profile, incomplete cue map, absent engine session, failed human observation, or
missing acceptance mandate cannot be averaged away.

## Organ law

| Organ | Owns | Does not own |
|---|---|---|
| Arc | action law, semantic cues, mechanic learning, replay, accepted receipt, consequence | renderer, camera, animation, provider, human evidence |
| World | input ingress, one presentation adapter, engine candidate, player surface | damage, timing, objective, outcome, accepted receipt |
| Tier Bench | provider qualification, substitution, resource and latency measurement | permanent provider selection or product acceptance |
| Tools | read-only trace, cue, response, and mismatch inspection | source mutation or verdict |
| Hinge | invalidator proposals and drift evidence | automatic rejection or repair authority |
| Embodied | attributed player, device, accessibility, and physical evidence | gameplay law or acceptance |
| Bloodstream | crash-recoverable job circulation | admission, provider choice, execution, or acceptance |
| Named authority | accept, hold, refuse, supersede, or revoke under mandate | evidence rewriting or silent delegation |

## Evidence ladder

```text
source
  contract and code are present

conformance
  the same spec, trace, state, and cue vectors reproduce

engine
  the real Unity/browser/Windows venue imports, runs, measures, and preserves law

human
  an independent player encounters the exact build without hidden assistance

acceptance
  a named authority acts on the complete evidence under an explicit mandate
```

A higher tier does not repair a lower-tier failure. A polished human session cannot
make parallel gameplay law acceptable. Perfect replay cannot prove that a player
understood the parry cue.

## Drift correction

The catalog defines fifteen current drift classes, including:

- parallel gameplay runtime;
- fixture presented as product;
- presentation mutation of state;
- primitive fallback in a player profile;
- timing inferred from animation rather than Arc;
- mandatory mechanic before teach and practice;
- source tests presented as player acceptance;
- self-issued human receipt;
- provider lock-in;
- challenge-ID gameplay branch;
- receiver trace divergence;
- debug surfaces competing with play;
- accessibility profile drift;
- hidden network or runtime download;
- representation-role counts presented as production assets.

Each class names its owner, signals, default response, and correction. A new class
requires a failure default and a negative witness.

## Worked UNDERDRAIN contract

The committed player intent requires:

```text
Mrs. Kett safe mechanism
→ attack and dodge introduction
→ safe parry lesson with forgiving Arc-owned timing
→ optional parry advantage during Pump Seven
→ Crown mastery using the same cue language
→ dodge or exhaustion as an explicit shorter alternate work opening
→ exact Arc consequence
→ playable Root Gate
```

The runtime and author may not issue the independent player receipt. A negative
session remains evidence.

## Contribution contract

A new entrant must identify the object being changed, declare the touched planes,
accept the owner derived by the floor, preserve rollback, add or update the relevant
negative witness, and run the complete reconstruction. Provider-specific fields may
not enter the player intent. Presentation code may not mutate state. Source or fixture
qualification may not be described as player acceptance.

Read [`START_HERE.md`](START_HERE.md) before editing. Read
[`CONTINUITY.md`](CONTINUITY.md) before changing a format, owner, gate, drift class,
or authority boundary.

The control question is whether one exact authored encounter can feel excellent in
browser, Unity, Windows, controller, and later XR while every presentation supplier
remains replaceable and every accepted outcome remains reconstructable from Arc law.
